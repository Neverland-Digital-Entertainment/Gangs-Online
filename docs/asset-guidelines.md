# 實習生資產規格文件（後台量產大廈 / 街道物件）

> 適用範圍：所有透過後台 Map Editor 上載到「資產庫」（`building_assets`）、
> 之後可以在地圖上重複擺放（instancing）的 GLB 資產，包括大廈、街道物件
> （props）與貼地平面（decal）。
>
> 座標系與規格：Fable ／ 執行：Sonnet ／ 日期：2026-08-02

## 1. 座標系

- **Y-up**：Y 軸向上，X/Z 為水平面。
- **原點在大廈底部中心（貼地）**：模型的座標原點 `(0, 0, 0)` 必須對齊
  建築物底部與地面接觸的中心點，唔可以係模型的幾何中心（否則放到地圖上
  會浮空或陷落地下）。
- **1 單位 = 1 米**：匯出時請確認 Blender 場景單位設定為公制（Metric），
  1 Blender 單位 = 1 米，唔好用預設的其他單位系統再手動換算。

## 2. Poly（三角面）預算

| 資產類型 | 上限（三角面數） |
|---|---|
| 大廈（building） | ≤ 3000 tris |
| 街道物件（prop） | ≤ 800 tris |
| 貼地平面（decal） | ≤ 50 tris |

超支的資產請先做 LOD 簡化（Decimate modifier 或手動減面）再匯出。
量產大廈的重點是「重複擺放」，poly 數對效能的影響遠低於材質/draw call，
但仍要克制，避免單一資產變成場景中最重的一份幾何。

## 3. 貼圖

- 解析度上限 **1024×1024**；貼地平面/細節較少的物件建議用 512×512 甚至更細。
- 格式：**WebP 或 PNG**（避免 JPG 的邊緣壓縮瑕疵影響透明邊界）。
- **鼓勵同系列資產共用同一張 atlas**（例如同一款招牌的多個變化版本），
  減少貼圖數量、有利 GPU 記憶體與下載大小。
- **GLB 檔案總大小上限 10MB**（含所有貼圖），系統會在上載時擋掉超過此
  上限的檔案；實務上建議盡量壓細，越細載入越快，Firestore 免費方案的
  讀寫額度亦有限。

## 4. 命名規範

- **mesh 名稱要有意義**：會直接顯示喺後台 Map Editor 的 outliner（物件
  清單）中，例如 `Shop_Front`、`AC_Unit_01`，唔好留低 Blender 預設的
  `Cube.001`、`Plane.003` 等名稱。
- **名稱講「呢件係乜」，唔好講「配邊個」**：地舖與上層是多重拼合關係
  （例如唐樓上層 5 款、單棟大廈上層 5 款，同一個地舖／大廈入口可以配任何
  一款）。把配對關係寫死在名稱只會限制自己。
  - ✅ `唐樓上層01`、`單棟上層03`、`地舖-茶餐廳A`、`大廈入口02`
  - ❌ `唐樓A_專用地舖`、`地舖B_配唐樓`
- **`_Lower` / `_Upper` 後綴並非必須**：後台擺放的資產，遮擋分組**一律**
  由 Map Editor 的遮擋群組（`groupId`）決定，與 mesh 名稱完全無關；配對
  發生在「擺放的那一刻」，不是在命名時。名稱後綴只在底圖內建大廈（政府
  資料）那條舊路徑才有作用。想用來自己辨認就用，不用亦完全沒有影響。

## 5. 匯出設定

匯出格式：**glTF Binary (.glb)**（唯一支援格式，方便單檔上載/下載）。

匯出前處理：
- **Apply Transforms**（`Ctrl+A` → All Transforms）：確保 position/
  rotation/scale 都已烘焙到幾何本身，匯出的 `__root__` 節點以下每個
  物件都應該處於乾淨的初始變換，避免匯入後出現非預期的旋轉/縮放。
- **唔好用 Draco 壓縮**：目前客戶端與後台 loader 未啟用 Draco 解碼器，
  壓縮過的 GLB 會載入失敗。匯出對話框內確認 Draco 選項關閉。
- **材質用 Principled BSDF**：Blender 匯出 glTF 只完整支援 Principled
  BSDF 節點（對應 PBR metallic/roughness 工作流程），其他節點組合
  （例如自訂 Shader Node Group）好可能匯出後貼圖/透明度唔正確。

## 6. 上載流程

1. 後台登入，前往「地圖」→「資產庫」（Map Editor 的資產分頁）。
2. 點擊「上載資產」，選擇已匯出的 `.glb` 檔案。
3. 填寫：
   - **名稱**：內部辨識用，建議與 mesh 命名風格一致。
   - **用途（kind）**：見第 7 節，務必揀啱，直接影響碰撞/可選取/遮擋行為。
   - **分類（category）**、**預設縮放（defaultScale）**、**標籤（tags）**：
     選填，方便日後搜尋與批次調整。
4. 上載完成後，資產會出現在 Map Editor 的資產選擇器，可以在任何 chunk
   拖放擺放（`add`）或替換既有建築（`replace`）。
5. 同一份資產可以在地圖上擺放任意次數——系統會共用同一份幾何與材質
   （instancing），draw call 唔會隨擺放次數線性增加。

## 7. 用途（kind）揀法

上載資產時必須指定其中一種：

| kind | 說明 | 碰撞 | 可選取 | 參與遮擋淡出 |
|---|---|---|---|---|
| `building`（預設） | 實心建築（住宅樓、商舖等） | 有（方塊碰撞體） | 有 | 有 |
| `prop` | 街道物件（垃圾桶、路牌、冷氣機等） | 有 | 有 | **無** |
| `decal` | 貼地平面（路面箭嘴、斑馬線、渠蓋等） | 無 | **無** | 無 |

- `prop` 不參與遮擋淡出：玩家行到它後面唔會令佢變透明，因為街道物件通常
  細細件，變透明反而奇怪。
- `decal` 無碰撞、不可選取，並自動套用深度偏移（polygon offset）避免與
  路面貼圖 z-fighting（閃爍）。揀錯 kind 會令貼地平面阻擋點擊移動，或者
  令冷氣機一類細物件參與遮擋。

## 8. 遮擋群組（groupId）概念

- 一棟大廈可以拆成多個獨立資產分開擺放（例如地舖層一件、上層樓層一件），
  但兩者應該被當成同一棟大廈一齊淡出，唔可以各自獨立判斷。**配對關係唔係
  寫死喺資產名稱，而係喺擺放時用 `groupId` 指定** —— 所以同一個地舖資產
  今日配唐樓、聽日配單棟大廈都完全冇問題。
- 後台 Map Editor 支援「建立群組」：選取多個已擺放的資產（列表多選），
  點擊「建立群組」，即可將佢哋標記為同一個 `groupId`；同一群組內的所有
  實例會在玩家走到後面時**一齊**變透明、一齊恢復。
- 唔屬於任何群組的擺放，預設以其唯一的 override key 自成一組，不會影響
  其他同款資產（即使係同一份 GLB 重複擺放一百次，各自遮擋互不牽連）。
- 群組可以隨時在後台重新命名或解散（見 Map Editor 右側面板的「遮擋群組」
  區塊）。

## 9. 常見錯誤檢查清單

- [ ] 原點喺底部中心，唔係幾何中心
- [ ] Blender 場景單位係公制、1 單位 = 1 米
- [ ] Poly 數喺預算之內
- [ ] 貼圖 ≤1024×1024，格式 WebP/PNG
- [ ] mesh 名稱有意義，非 Blender 預設名
- [ ] 已 Apply Transforms
- [ ] 匯出未開 Draco
- [ ] 材質用 Principled BSDF
- [ ] 上載時 kind 揀啱（building/prop/decal）
- [ ] GLB 總大小 ≤10MB（越細越好）
